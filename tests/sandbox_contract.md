# Исполнитель экспериментов: первый контракт

Файл: `agent/sandbox.py`. Ответственность: исполнить готовый Python-код,
вернуть диагностический результат и пути к ожидаемым выходным файлам.
Общие `contracts.py`, ML-пайплайны и оркестратор пока не изменяются.

```python
from dataclasses import asdict
from agent.sandbox import run_experiment

result = run_experiment(
    code=generated_python,
    work_dir=experiment_directory,
    timeout_sec=120,
    memory_limit_mb=4096,
    cpu_limit=2,
    expected_outputs=('validation_predictions.csv',),
)
# Для JSON/истории: asdict(result).
```

Вызывающая сторона создаёт отдельную папку для каждого эксперимента,
размещает входные данные и сообщает их пути генератору кода. Код запускается
в этой папке с тем же Python и установленными библиотеками, что и исполнитель.
Вход stdin закрыт. Интерактивный ввод не поддерживается.

## Результат

- `status`: success, error, timeout, memory_limit.
- `stdout`, `stderr`: хвост вывода, по умолчанию не более 64 КиБ байтов до
  декодирования каждого потока; флаги `*_truncated` показывают обрезку.
- `exit_code`, `duration_sec`, `peak_memory_mb`, `error`.
- `output_files`: абсолютные пути найденных ожидаемых файлов.
- `missing_outputs`: ожидаемые файлы, которых нет или путь которых выходит
  за рабочую папку. При успешном завершении кода их отсутствие даёт error.

Неверные аргументы вызывают исключение до запуска. Ожидаемые выходные файлы
не должны существовать до эксперимента: старый результат нельзя принять за новый.
Файлы после неудачного запуска могут быть частичными. Их наличие не означает
успеха и не даёт права заменять лучший submission.

## Кто делает остальное

- Генерация и исправление кода: LLM-блок.
- Подготовка разбиения, независимая оценка предсказаний: модуль валидации.
- Принятие гипотез, журнал, глобальный дедлайн: AutoResearch/оркестратор.
- Финальное обучение и проверенная атомарная запись submission: интеграция/ML.

Лимиты одного запуска выделяет оркестратор с учётом общего бюджета задачи.
`cpu_limit` задаёт CPU affinity и переменные потоков популярных ML-библиотек.
Он не резервирует ядра эксклюзивно. Не запускайте суммарно больше ресурсов,
чем выделила платформа. Память оркестратора и других экспериментов также учитывайте.

## Границы защиты

Только Linux/WSL. Используются стандартные библиотеки Python, установка не нужна.
RSS суммируется по группе процессов примерно каждые 20 мс. Общие страницы могут
учитываться несколько раз, краткий скачок может быть пропущен. Это не жёсткий
лимит памяти ОС. При таймауте, превышении памяти и завершении родителя группа
процессов завершается. Намеренный выход кода из группы процессов не поддерживается.
Для строгих гарантий нужны внешние ограничения ОС (например, cgroups).

Это НЕ изоляция файловой системы/сети. Код имеет доступ к файлам текущего
пользователя. Ключи из окружения не передаются, но это не защищает секреты в файлах.
Не считать скрытые ответы валидации защищёнными этим исполнителем.
Метрики, напечатанные кодом, не являются доверенным результатом оценки.

## Проверка и упаковка

Из корня проекта в WSL:

```sh
.venv/bin/python -B -m unittest discover -s tests -p 'test_sandbox.py' -v
```

Для ZIP файл `sandbox.py` можно разместить в корне и импортировать как
`from sandbox import run_experiment`: зависимостей от пакета agent нет.
Тесты и этот документ в сдаваемый архив не нужны.
